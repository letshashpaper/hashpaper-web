Technical Architecture & Cryptographic Specification

Zero-Knowledge Timestamping Methodology

HashPaper separates proof of existence from content disclosure. By computing SHA-256 digests strictly inside the creator's browser before any network transmission, intellectual property remains confidential while gaining verifiable priority.

STAGE 01 • CANONICALIZATION

Deterministic UTF-8 Byte Encoding

Operating systems encode line endings differently (\r\n on Windows vs. \n on macOS/Linux). HashPaper standardizes line endings to LF (\n) and encodes text into raw UTF-8 bytes so the resulting digest is identical across every device and OS.

STAGE 02 • LOCAL DIGEST

Web Crypto API SHA-256 Execution

Using the native browser window.crypto.subtle.digest('SHA-256') engine, your normalized byte buffer is reduced into a 256-bit (64-character hexadecimal) cryptographic fingerprint. The raw text never traverses the network.

STAGE 03 • DUAL ANCHORING

IST Database + OpenTimestamps Ledger

Upon payment verification, Cloudflare Edge Functions commit the 64-character digest to our Mumbai (ap-south-1) PostgreSQL ledger with an authoritative IST timestamp and simultaneously submit the raw 32-byte digest to public OpenTimestamps calendar servers.

STAGE 04 • PARITY ARTIFACT

Unaltered Reference File & Blind Ledger

Your browser downloads the exact hashed byte stream as HashPaper_Ref_XXXX.txt, while a database trigger mirrors only the Certificate ID, hash, masked initials, and timestamp to the public verification ledger.

Independent Command-Line Parity Verification

Because HashPaper hashes pure UTF-8 bytes without proprietary wrappers or hidden salts, any forensic examiner or court expert can independently recompute the exact same SHA-256 hash from your downloaded .txt file using standard OS utilities:

# Windows PowerShell: Get-FileHash .\HashPaper_Ref_XXXXXXXXXXXX.txt -Algorithm SHA256
# macOS Terminal: shasum -a 256 HashPaper_Ref_XXXXXXXXXXXX.txt
# Linux Terminal: sha256sum HashPaper_Ref_XXXXXXXXXXXX.txt
